# AI 学童（单词）：发布与评估

旧文中的“小老师”指当前的 AI 学童。迁移编号与评估口径用于该功能；当前整体迁移状态、部署版本和隐私配置须另行核查。

## 发布

先按现有受控迁移流程核验并应用 `029_tutor_learning.sql`，再发布依赖该表的 API 和小程序。不要在受控迁移账本之外手工执行迁移。隐私政策内容和版本已更新，用户需要重新确认；小老师首次使用提示也说明了年级和练习记录的处理。部署时应检查线上政策、服务商配置、音频计价和小程序域名配置。

## 指标口径

`word_tutor_learning_events` 记录小课打开、练习开始、练习回答、用户主动完成，以及三类讲解反馈；删除会话时级联删除，注销账号时删除该账号产生的事件。事件不包含自由文本。事件收集是尽力而为：网络中断可能导致漏记，直接聊天也不一定被认作练习，不能将计数解释为完整学习人数或掌握率。`exercise_completed` 表示用户主动确认本次练习完成，不表示答案一定正确或长期掌握。

例如按会话去重统计各事件：

```sql
SELECT kind, count(*) AS events, count(DISTINCT session_id) AS sessions
FROM wordmate.word_tutor_learning_events
WHERE created_at >= $1 AND created_at < $2
GROUP BY kind ORDER BY kind;
```

练习漏斗需要按同一批首次看到讲解的会话分组，并明确时窗；不能直接用不同日期事件总数相除。延期复习表现需要另外设计与现有复习记录的关联和评估，不可从用户点击完成推断。

## 上线前体验检查

使用经过人工核对的不同词性、不同词义、易混词及没有例句的词条，分别测试低、高年级和未填年级：检查解释、搭配、英文例句与翻译，确认练习不泄露答案；测试正确、错误、含糊答案以及请求答案后的反馈。用微信开发者工具和真机检查首次进入、等待、失败重试、语音和键盘、返回学习、旧聊天记录、扣费提示与删除。重点比较真实模型结果及各服务商的结构化输出能力。采集的问题反馈需要人工核查，不能作为模型正确性的自动证明。

文字导入使用“整理后选择”：候选数据保存在生成任务中，生成成功即按实际使用结算；用户逐页确认时不再调用模型。旧客户端继续使用原有直接保存流程。小老师的“其他意思”提供候选按钮，点击后先放入文字草稿；整理音标和例句会再次使用 AI，最终仍需用户选择确认。上线时先发布兼容旧客户端的 API，再上传小程序；验证大批量分页、重试、取消选择和服务中断恢复，以及真实模型的其他词义结构化输出。
