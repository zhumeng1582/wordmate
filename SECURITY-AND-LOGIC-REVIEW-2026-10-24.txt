一、优先处理

R01 [P1，命中公告/默认配置满足前提；本轮未完成真实 HTTP 崩溃复现] 请求解析器存在未登录拒绝服务风险
位置：apps/api/src/main.ts:142–143；pnpm-lock.yaml 的 body-parser@2.3.0。
实际依赖链：@nestjs/platform-express → express@5.1.0 → body-parser@2.3.0。运行环境的模块解析也确认此版本。
当前两处 JSON 解析器均未禁用压缩请求，普通接口解析发生在控制器鉴权之前；现有 Nginx 示例也未拒绝 Content-Encoding。
维护者公告 GHSA-27r3-jxmh-p828 描述压缩内容尾随字节可触发未捕获异常、导致进程退出，影响 2.x <2.4.0；给出的临时缓解为 inflate:false。
影响：按现有默认部署路径存在无需登录触发 API 停服的风险。不能用业务鉴权、普通异常 catch 或仅按 IP 限流替代修复。
建议：优先升级到已修补的兼容依赖组合，或先明确拒绝压缩 JSON；使用真实 HTTP 子进程回归畸形压缩请求、413/422 和正常导入。
来源：https://github.com/expressjs/body-parser/security/advisories/GHSA-27r3-jxmh-p828

R02 [P1，已复现] 删除孩子能重置同一账号的付费调用额度
位置：apps/api/src/audio.ts:93；apps/api/src/vocabulary.ts:83–84；apps/api/src/lifecycle.ts:188。
音频额度按 audio_usage_events 计数，词汇生成按 generation_jobs 的 attempts 求和；删除孩子会清除这两类记录。
复现：把账号音频每日额度设为 1 → 生成一次 → 删除该孩子且任务成功 → 同账号新建孩子并生成，第二次仍成功；期间未过一天。
结果：configured_user_daily_limit=1，synthesis_calls=2，删除后旧调用不再计入账号额度。全部使用替身 TTS，未产生真实费用。
影响：合法登录者可反复创建/删除孩子绕过账号额度，扩大模型费用。词汇生成存在相同的计费记录生命周期问题，未做真实付费调用验证。
建议：账号级最小用量/预算记录与孩子业务数据分开，按短期留存处理删除，同时提供供应商级费用上限。入队时也要限制待处理任务数，避免只限制执行而不限制队列膨胀。

R03 [P1，已复现] “生产检查通过”的配置无法创建 OSS 适配器
位置：scripts/check-production-env.cjs:26–27；packages/ai/src/oss-storage.ts:27–36；apps/api/src/audio-runtime.ts:23。
生产检查强制 OSS_CREDENTIAL_MODE=ecs_ram_role；实际 createOssStorage 只支持 ram_access_key / sts，并先读取静态 AccessKey。
复现：构造无真实凭证的完整测试配置，生产检查 passed=true，创建存储返回 OSS_CREDENTIAL_MODE_MISMATCH。实际 ECS 角色环境不提供静态 AccessKey 时会先报缺少 AccessKey。
影响：按准备文档配置生产角色后，音频/海报存储初始化失败，可能直接阻止 API 启动；检查门槛与实现不存在可同时满足的凭证模式。
建议：实现 ECS RAM 角色临时凭证获取与刷新，并让检查实际验证适配器初始化；不要以补一套长期密钥掩盖此冲突。

二、已复现的功能与数据边界缺陷

R04 [P2，已复现] 海报过期清理失败后丢失文件记录，后续删除仍报告成功
位置：apps/api/src/checkin-share-images.ts:96–101；apps/api/src/lifecycle.ts:187。
过期清理 storage.delete 的错误被吞掉，随后无条件删除数据库记录。孩子删除随后找不到该对象，也没有海报对象清单可补偿。
复现：给一个已过期的私有海报对象模拟存储删除拒绝 → 运行过期清理 → 删除对应孩子。
结果：objects_left=1、assignment_rows=0、child_deletion_status=succeeded。
影响：文件会失去追踪，删除完成状态无法证明相关文件已清理；当前海报背景不含孩子身份和叠加学习文字，本轮未复现学习记录泄漏。
建议：删除成功/明确不存在后才删元数据；失败保留待清理记录；把海报对象也加入持久删除清单。历史孤儿对象需通过受限前缀清点修复。

R05 [P2，已复现] 月测未答题提前下发正确答案，前后端答题规则不一致
位置：apps/api/src/quiz.ts:90–100；apps/miniapp/src/pages/quiz/index.tsx:21、29、53。
测验进入 in_progress 后，items 对整页题目返回 correct_option_id，包括尚未作答的题目。前端选择后锁按钮，服务端仍允许使用最新 answer_version 改答。
复现：两道未答题均拿到正确选项；提交错误选项后，再按返回的正确选项提交，服务端接受修改。
影响：即使希望提供即时反馈，也不需要提前暴露未答题答案。当前成绩可被“看答案后改答”改变，且与 PRD 的“未交卷 DTO 不含正确答案”冲突。
建议：统一测验模式。若作答后即时反馈，服务端仅对已成功保存的答案返回反馈，并明确是否锁定首次作答；若允许考前改答，应把正确答案留到交卷后。保持已提交结果不可变。

R06 [P2，已复现] 归档词本后，旧学习会话仍能给已归档单词提交复习
位置：apps/api/src/core.ts:117、256–266。
归档会设置 child_words.archived_at / review_cards.suspended_at，但既有会话取卡与 review 未重新校验这两个状态。
复现：建立学习会话 → 删除该单词唯一所在词本 → 旧会话仍返回 1 张卡 → 提交答案成功，当日已学数增加到 1。
影响：用户已移出学习列表的词仍能被继续学习，修改调度并计入统计/打卡；这不是跨家庭访问，但会造成“删除后仍继续学习”的行为矛盾。
建议：归档时撤销/裁剪相应学习队列，取卡及新答案提交前复核归档/暂停状态；历史已成功答案的幂等重放仍应安全返回原结果。

R07 [P2，已复现] 补签改变连续记录起点，触发重复发放奖励卡
位置：apps/api/src/core.ts:196–208、274；apps/api/migrations/012_checkin_makeup.sql 的唯一键。
奖励去重依赖 child_id + streak_start + milestone_days。补签可把当前连续记录向前延伸，streak_start 改变，下一次复习就把原有 15 天里程碑当作新奖励。
复现：真实连续达标 15 天得到 1 张卡 → 补签连续段之前一天 → 同日额外练习再获卡 → 再补签更早一天并额外练习。
结果：只完成原本 15 天达标，奖励记录 total=3、used=2、available=1，可继续向前重复。
影响：补签卡和连续天数能被循环刷取，激励规则不可信。
建议：为奖励采用不随补签改变的领取凭据，明确奖励是否只计算实际学习日；补签不能重发已领取里程碑，补迁移需要处理历史重复奖励。

R08 [P2，已复现] 另一位家长重新编辑失败任务后，Worker 仍检查原家长授权
位置：apps/api/src/vocabulary.ts:53–55、75。
retry 会更新 requested_by，replace 编辑分支没有更新。
复现：爸爸的生成失败 → 爸爸撤回同意 → 仍有有效授权的妈妈重新编辑同一任务 → 接口成功返回 queued → Worker 继续以爸爸为请求者验证，任务变为 failed / GENERATION_FAILED。
影响：家庭接力编辑看似提交成功却无法继续，错误还被归类成普通生成失败。保护没有绕过，但合法家长操作不能完成。
建议：编辑重提由当前发起人显式承担新请求，更新 requested_by，并保留必要审计；同时保持未授权原请求不自动恢复。

R09 [P2，角色规则不一致，已复现] 普通家庭成员可创建孩子档案
位置：apps/api/src/core.ts:108–112；apps/miniapp/src/pages/family/index.tsx 的添加孩子入口。
createChild 只验家庭成员，无 owner 检查；前端也为共同家长展示添加按钮。现有 PRD 将创建/删除孩子列为管理员能力。
复现：获批普通家长调用 createChild 成功。
影响：管理员角色约定与实际权限不一致；未发现该路径允许跨家庭创建。
建议：按已定管理员规则在服务端检查 owner 并同步页面，或明确修改产品权限表后统一契约；不能只隐藏按钮。

R10 [P2，客户端替身已复现] 旧账号请求迟到的 401 会清掉新账号登录状态
位置：apps/miniapp/src/services/api.ts:7–14。
api 捕获了请求开始时的 token，但处理 401 时无条件 clearAccountStorage，没有确认该请求是否仍属于当前登录会话。
复现：用旧 token 发请求并挂起响应 → 本机切到新 token → 旧响应返回 401 → 新 token 和新账号存储被清空。
影响：切换账号/重新登录时可能突然退出、丢失本机待同步状态。未发现此路径把旧账号令牌提供给新账号。
建议：响应处理绑定会话代次/请求 token，只有当前会话的 401 才能清理该会话；过时请求不能清除或覆盖新账号状态。

三、静态路径发现，待专项复验

S01 [P2，未真机复现] 切换家庭后没有清除或校验当前孩子
位置：apps/miniapp/src/pages/family/index.tsx:17–26、家庭底部“继续学习”按钮。
select(f) 更新 family_id，却保留原 child_id。普通家长切换到另一家庭后，按钮用 children.find(oldChildId) 调 chooseChild，可能传入 undefined 并访问 c.id；其他页面也可能继续显示原家庭孩子。
建议：家庭切换同时校验 child_id 归属，清空或选择本家庭孩子；异步结果加作用域校验。需要 Android/iOS 复验多家庭切换和并发返回。

S02 [P2，锁顺序冲突已静态确认；实际死锁未复现] 标注写入与归档/删除可能形成锁循环
位置：apps/api/src/core.ts:186 对 child_words 先 FOR UPDATE，再调用 child() 锁家庭；archiveWordbook 和 Lifecycle 则先锁家庭/孩子，再修改/删除 child_words。
并发时可能出现“标注持有单词锁等待家庭锁，归档持有家庭锁等待单词锁”的循环。
本机只有 PGlite 路径，事务被串行化，90 项测试不能覆盖真实 PostgreSQL 多连接死锁。
建议：统一家庭 → 孩子 → 业务资源的锁顺序，数据库配置合理 statement_timeout / lock_timeout，并在 PostgreSQL 双连接回归标注/归档/删除竞态。
